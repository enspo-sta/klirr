# Klirr

Klirr is a nonlinear loudspeaker simulator that runs in the browser. It integrates Klippel's lumped-parameter
driver model (Bl(x), Kms(x), Le(x) with the L2/R2 branch and reluctance force, Doppler, adiabatic box air,
port jet loss, passive radiators) in time, and from that one model reports harmonic, intermodulation and
multitone distortion, voice-coil offset, compression, maximum SPL, and an A/B listening test on music.

The whole app ships as one self-contained HTML file with no network dependencies. It is published two ways:
GitHub Pages (`dist/index.html`, built by the workflow on every push to `main`) and a private Claude artifact
(`dist/klirr.html`, the same page without the document skeleton, which the artifact host adds).

## Layout

| Path | What it is |
| --- | --- |
| `engine.js` | The simulation engine. UMD: `require('./engine.js')` in Node, `KlirrEngine` in the page, and a Web Worker protocol. No DOM. |
| `src/template.html` | Page skeleton and the full Guide text, with `{{CSS}}`, `{{LIBRARY}}`, `{{ENGINE}}`, `{{APP}}` placeholders. |
| `src/app.css` | Single dark theme. Tokens on `:root`. |
| `src/core.js` | DOM helper `h()`, number formatting, the canvas `Plot` class, the worker client `Compute`, storage `Store`. |
| `src/app_state.js` | App state, default settings and example setups, tabs, compare chips, form helpers. |
| `src/views_analysis.js` | Distortion, Intermodulation, Multitone and Max SPL views. |
| `src/views_listen.js` | Listen view (auralisation and playback). |
| `src/views_manage.js` | Setups and Drivers editors, import and export. |
| `src/main.js` | Start-up, Guide contents column, account sync. |
| `library.json` | Built-in drivers. Generated by `build_library.py`; never edit by hand. |
| `research/` | Pixel-extraction scripts, their configs and outputs, and the review metadata the library is built from. |
| `tests/` | Engine validation, measured comparison, browser tests. |
| `build.py` | Writes `dist/klirr.html`, `dist/index.html` and `dist/harness.html`. |

The app files in `src/` are concatenated in the order listed in `build.py` (`APP_FILES`) into one script, so
top-level functions are shared between them.

## Commands

```bash
python3 build.py              # build dist/
npm test                      # engine checks, API smoke test, measured comparison, independent reference (about 30 s, no browser)
npm install                   # once, for the browser tests
npm run test:browser          # build, then four Playwright runs; screenshots land in shots/
python3 build_library.py      # regenerate library.json from research/
npm run serve                 # http://localhost:8000 serves dist/
```

Run `npm test` after any change to `engine.js`, `library.json` or `research/` (when the built-in curves change, also
`python3 research/reference/run_reference.py`, which needs numpy, to refresh the independent reference), and `npm run test:browser`
after any change to `src/`. Look at the screenshots in `shots/` after visual changes.

In a cloud session the network may block the headless-browser download (`npx playwright install chromium`).
If so, run `npm test`, push the branch, and read the "Page in a headless browser" job in GitHub Actions,
which runs the four browser tests on every push and pull request and keeps their screenshots as an artifact.
Rerunning the extraction needs network access to `erinsaudiocorner.com` and `dl.dropboxusercontent.com`
and the `tesseract` program.

## Rules

- **The Guide's numbers are checked.** `tests/test_engine.js` and `tests/cmp_erin.js` fail when the engine no longer
  reproduces the validation tables in the Guide (`src/template.html`). If a change is intended, rerun them and
  update the Guide's tables and their check values together, in the same commit.
- **Measurement first.** Driver curves come from measurements: Klippel LSI coefficients, or pixel extraction
  with the pipeline in `research/lsi` (OCR-read tick labels paired with gridlines, every labelled tick a check,
  largest residual below 1 px, exact colour mask, overlay image checked by eye). Never estimate a curve and
  present it as measured. An estimate gets `"badge": "estimate"` and a note saying what it is based on.
- **Every driver entry names its source** with a direct URL, the retrieval date, and what was taken from it.
  Never merge two drivers' data or two sources into one entry.
- **Erin's Audio Corner images are not committed.** `research/lsi/fetch_sources.py` downloads them from the URLs
  in `research/lsi/sources.json` when the extraction needs to be rerun.
- **Keep empirical and inferred apart** in the Guide: what was measured or computed, then what it implies.
- **Storage:** `Store` uses the Claude artifact database when `window.claude` exists, and browser storage
  otherwise. Document ids may only contain letters, digits and `_ - . ~ : @ +`. Keep both paths working;
  `tests/runtime_test.js` covers the artifact path with a mock.
- **Artifact limits** apply to `dist/klirr.html`: no external requests except allowlisted CDNs, no `alert`,
  `confirm` or `prompt`, no `<a download>` inside the artifact (the code already branches on `window.claude`).
- **Look:** one dark theme, system fonts, no new colours outside the tokens in `app.css`. Text in plain English,
  no invented abbreviations.

## Publishing

- GitHub Pages: push to `main`. The workflow runs all tests and deploys `dist/` to
  https://enspo-sta.github.io/klirr/.
- Claude artifact: the artifact named Klirr in the owner's claude.ai gallery. When a session has the Artifact
  tool, update it by publishing `dist/klirr.html` with that artifact's link as `url`, and keep its capabilities
  (`db`, `user`, `downloads`).
